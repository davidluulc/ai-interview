# v3 切生产默认 + MCP 租户隔离启用（含发布）

## 背景与目标

- 用户决策：无真实流量，shadow 观察等不来 → **LangGraph v3 直接切生产默认**；**MCP 推进到生产可用**（租户隔离+鉴权+启用）；监控/备份暂不做。

- 探索发现的三个必须修的点：路由层从不派发 v3；payload 缺 v3 必需键；**end_interview 空问题会被质量门误杀**（tests/test_langgraph_agent_v3.py:506-553 已钉住该行为）。

2. `agent_runtime.py`：
   - `normalize_agent_runtime` 默认值 → `langgraph_agent_v3`

   - 守卫 :917 与三元 :972-978 加入 v3
   - payload :982-985 补 `profile/history/next_stage/agent_mode/application_profile_id/user_id`（全部在作用域内现成可得）

## 工作流 B：MCP 租户隔离 + 鉴权 + 生产启用

### 服务端（mcp_server/，官方 SDK 2.2.0 `MCPServer`）
10. 5 个工具加 `ctx: Context` 参数，经 `ctx.headers["x-user-id"]` 取真实用户 id（缺省回落 `SERVICE_USER_ID=1`，兼容 stdio/演示），全部检索按该用户隔离（私有数据只看自己的+公共数据）。
11. 共享密钥：`MCP_AUTH_TOKEN` 环境变量（设置时校验 `x-mcp-token` 头，不匹配 401；不设=本地开发不拦）。用 SDK 原生钩子（`token_verifier`/`middleware`），若两者都不适配则在 `run_http.py` 自起 uvicorn 挂 Starlette 中间件（SDK `streamable_http_app()` 支持）。

### 客户端（backend_python/mcp_tools_client.py）
12. `build_streamable_http_factory(url, *, headers)`：SDK 2.2.0 的正道是传预配置 `httpx.AsyncClient`（`http_client=` 参数），注入 `x-user-id` + `x-mcp-token` 头。
13. `build_mcp_tool_fns(..., *, user_id)`：进程内 fallback 闭包用真实 user_id（现在硬编码 None）。
14. `agent_runtime.py` v3 分支：工厂带头部（用户 id 来自 payload + `MCP_AUTH_TOKEN` 配置），fallback 闭包带 user_id。
15. 测试：服务端按 x-user-id 隔离（A 看不到 B 私有文档）、token 拒绝、客户端头部注入（扩展现有 assembly 测试）、fallback 用户隔离。
16. `docker-compose.yml` / `.env.production.example`：加 `MCP_AUTH_TOKEN` 变量与说明。
